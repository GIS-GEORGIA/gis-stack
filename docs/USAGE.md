## 1. რა მჭირდება

| რა | შენიშვნა |
|---|---|
| Linux (Debian/Ubuntu ან RHEL/Rocky/Alma/Fedora) | გამოცდილია: **Ubuntu 24.04**, **Rocky 9** |
| Python 3.9+ და `python3-venv` | `install.sh` თვითონ დააყენებს, თუ აკლია |
| რეალურ სერვერზე დაყენებისთვის | `root` ან მომხმარებელი პაროლის გარეშე `sudo`-თი (SSH-ით დაყენებისას) |
| Docker / Podman ან kubectl | მხოლოდ Compose / Kubernetes სამიზნეებისთვის |
| ინტერნეტი სერვერზე | პაკეტების, Tomcat-ის, GeoServer-ის და Caddy-ს ჩამოსატვირთად |

გირჩევთ პირველად სატესტო სერვერზე ან VM-ზე გაუშვათ.

## 2. პროგრამის დაყენება და გაშვება

```bash
git clone https://github.com/GIS-GEORGIA/gis-stack.git
cd gis-stack
sudo ./install.sh          # ყველასთვის: /usr/local/bin/gisstack
# ან: ./install.sh         # მხოლოდ შენთვის: ~/.local/bin/gisstack
# ან: ./install.sh --tk    # + Desktop GUI (ინსტალერი დააყენებს python3-tk-ს)
```

შემოწმება:

```bash
gisstack --version
```

გაშვების სამი გზა:

| ბრძანება | რა არის |
|---|---|
| `gisstack web` | **ვებ GUI** (ბრაუზერში) — რეკომენდებულია |
| `gisstack desktop` | Desktop GUI (Tkinter; საჭიროა `python3-tk`) |
| `gisstack ...` | ბრძანების ხაზი, GUI-ს გარეშე ([იხ. 9](#9-იგივე-ბრძანების-ხაზიდან)) |

> თუ `gisstack` ვერ მოიძებნა და `~/.local/bin`-ში დააყენე, დაამატე იგი `PATH`-ში:
> `export PATH="$HOME/.local/bin:$PATH"`.

ან `.deb` / `.rpm` პაკეტით: `packaging/build.sh deb` (ან `rpm`), შემდეგ `sudo apt install ./dist/gisstack-installer_*_all.deb`.

## 3. ვებ GUI-ის გახსნა

```bash
gisstack web
```

ტერმინალი დაბეჭდავს მსგავს ბმულს:

```
gisstack web installer 0.1.2
  open:  http://127.0.0.1:8765/?token=AbCd...
```

გახსენი ეს **სრული ბმული** (token-ით) ბრაუზერში. token დაცვაა: მის გარეშე გვერდი 401-ს აბრუნებს.

- ვებ GUI მხოლოდ `127.0.0.1:8765`-ზე უსმენს, ანუ გარედან მიუწვდომელია. სხვა პორტი: `gisstack web --port 9000`.
- token ინახება `~/.gisstack/web.token`-ში (root-ით გაშვებისას — `/root/.gisstack/web.token`, პაკეტით დაყენებისას — `/var/lib/gisstack-installer/web.token`).
- **GUI სერვერზე გაქვს, ბრაუზერი — შენს კომპიუტერზე?** გახსენი SSH გვირაბი შენს კომპიუტერზე:

  ```bash
  ssh -L 8765:127.0.0.1:8765 user@server
  ```

  შემდეგ ბრაუზერში გახსენი იგივე `http://127.0.0.1:8765/?token=…` ბმული.
- გასაჩერებლად ტერმინალში დააჭირე `Ctrl+C`.

## 4. ნაბიჯ-ნაბიჯ: სტეკის დაყენება ვებ GUI-დან

გვერდზე სექციები არის ზემოდან ქვემოთ. ძირითადი გზა:

1. **„1. ზოგადი"**: პროექტის სახელი (a-z, 0-9, `_`), **დომენი** და HTTPS რეჟიმი (იხ. [ცხრილი](#https-რეჟიმი)).
2. **„2. კომპონენტები"**: მონიშნე რა გინდა (PostGIS, Tomcat, GeoServer, QGIS Server, MapProxy, Caddy, ვებ რუკა, მობილური შაბლონები).
3. **სექციები 3–6**: თითოეული მონიშნული პროგრამის პარამეტრები და ვერსიები ([იხ. 5](#5-პროგრამებისა-და-ვერსიების-არჩევა)).
4. **„7. სამიზნე და Deploy"**: აირჩიე *რა დაგენერირდეს* (native / Compose / Kubernetes), *რომელი გავუშვა* და *სად* ([იხ. 6](#6-სად-გაეშვას-zip-ეს-მანქანა-ssh)).
5. დააჭირე **„წინასწარი ნახვა"**: მარჯვნივ ჩანს გენერირებული ფაილები (პაროლები დაფარულია). ეს არაფერს ააყენებს.
6. დააჭირე **Deploy**, დაადასტურე. მარჯვენა ლოგში მიმდინარეობა ჩანს; ბოლოს **✔ დასრულდა**.
7. გადადი სექციაზე **„9. დიაგნოსტიკა"** და დააჭირე „განახლება": უნდა ნახო ყველა პროგრამა `running` სტატუსით და ✔ შემოწმებებით.

პაროლები ავტომატურად გენერირდება, თუ ველს ცარიელს დატოვებ. სად ინახება: native — სერვერზე `/etc/gisstack/credentials.txt`
(root-ით წასაკითხი); Compose — `compose/.env`, Kubernetes — `k8s/secret.yaml` დაგენერირებულ ბანდლში
(GUI-დან გაშვებისას ის `~/.gisstack/bundles/<პროექტი>-…/` საქაღალდეშია).

### HTTPS რეჟიმი

| არჩევანი | როდის |
|---|---|
| **ავტომატური Let's Encrypt** | რეალური დომენი, რომელიც სერვერზე მიუთითებს; ველში ჩაწერე ელ-ფოსტა; პორტები 80 და 443 ღია |
| **Caddy-ს შიდა CA** | `localhost`, ინტრანეტი, ტესტი; ბრაუზერი გაფრთხილებას აჩვენებს (სერტიფიკატი არ არის სანდო) |
| **HTTP მხოლოდ** | TLS-ის გარეშე (მხოლოდ დახურულ ქსელში) |

> `localhost`-ისთვის „ავტომატური" არ მუშაობს — GUI ამას შეგატყობინებს.

## 5. პროგრამებისა და ვერსიების არჩევა

### კომპონენტები (სექცია 2)

| კომპონენტი | რას აკეთებს |
|---|---|
| PostgreSQL + PostGIS | სივრცითი ბაზა |
| Apache Tomcat | Java კონტეინერი (GeoServer-ისთვის **ავტომატურად** ემატება native-ზე) |
| GeoServer | WMS / WFS / WMTS |
| QGIS Server | QGIS პროექტების გამოქვეყნება |
| MapProxy | ტაილების ქეში, WMTS, seed |
| Caddy | ერთი შესასვლელი `/`, `/geoserver`, `/mapproxy`, `/qgis` + HTTPS |
| ვებ რუკა | ორენოვანი (KA/EN) Leaflet რუკა, უკვე მიბმული შენს ფენებზე |
| მობილური რუკები | React Native და Flutter შაბლონები (ფაილებად, არ ინსტალირდება) |

### რომელი ვერსიის არჩევა შეიძლება ვებ GUI-ში

| რა | სად | არჩევანი |
|---|---|---|
| **PostgreSQL** | სექცია 3, „ვერსია" | 18, 17, 16, 15, 14 (გამოცდილია **17**) |
| **GeoServer** | სექცია 4, „GeoServer ხაზი" | **3.0** (3.0.2, სტაბილური) ან **2.28** (2.28.6, მხარდაჭერილი) |
| **Tomcat** | თავისით, GeoServer-ის არჩევანით | GeoServer 3 → **Tomcat 11**; GeoServer 2.28 → **Tomcat 9** |
| **Java** | თავისით, იგივე არჩევანით | 17 |

GeoServer 3.0 არ მუშაობს Tomcat 10.1-ზე; GUI ამას ზუსტად ამიტომ არ გაძლევს ამ კომბინაციას. სექცია 4-ში ირჩევ ხაზს და ქვემოთ წერს,
რომელი Tomcat და Java გამოიყენება.

### დამატებითი არჩევანი

| სექცია | რა |
|---|---|
| 3. PostgreSQL | ექსთენშენები მონიშვნით (PostGIS raster/topology, pgRouting, pointcloud, ogr_fdw, H3, hstore, pg_trgm, ...), RAM (GB) ტიუნინგისთვის, `max_connections`, გარე წვდომა + დაშვებული CIDR |
| 4. GeoServer / Tomcat / QGIS | GeoServer heap (MB), Tomcat heap (MB), QGIS პროცესების რაოდენობა, **GeoServer-ის გაფართოებები** (vectortiles, css, wps, importer, ysld, monitor, control-flow, inspire, ogcapi-features, mbstyle) |
| 5. MapProxy | ქეშის ტიპი (file / sqlite / geopackage), ფორმატი, workers, ფონი (არცერთი / OSM), **grid-ები** (3857, 4326, UTM 38N/37N), ფენები (სახელი, სათაური KA/EN, წყარო, WMS ფენა), წინასწარი seed |
| 6. ვებ რუკა | სათაური KA/EN, ნაგულისხმევი ენა, ცენტრი და zoom, ფონური რუკა |

### რაც მხოლოდ კონფიგურაციის ფაილშია (GUI-ში არ ჩანს)

ზუსტი პატჩ-ვერსია, საკუთარი image, პორტები და სხვა ხელით იწერება კონფიგურაციაში:

```bash
gisstack defaults > stack.json      # ნაგულისხმევი კონფიგურაცია, შეცვალე ველები
```

| ველი `stack.json`-ში | რას ცვლის |
|---|---|
| `geoserver.version` | ზუსტი GeoServer ვერსია (ცარიელი = არჩეული ხაზის ნაგულისხმევი) |
| `geoserver.image` | GeoServer-ის Docker image (Compose / k8s) |
| `tomcat.major` (`11`, `10.1`, `9`) | მხოლოდ **GeoServer-ის გარეშე** დაყენებულ Tomcat-ზე |
| `tomcat.port` | Tomcat-ის პორტი (ნაგულისხმევი 8080) |
| `k8s.postgis_image`, `k8s.mapproxy_image` | საკუთარი image-ები Kubernetes-ზე |
| `runtime` | `docker` ან `podman` |

**ხელით გაშვებისას** (ZIP-ით ან `gisstack generate`-ით მიღებული `native/install.sh`) ზოგიერთი ვერსია გარემოდანაც იცვლება:
`cd native && sudo TOMCAT_VERSION=11.0.20 JAVA_VERSION=21 ./install.sh`; `QGIS_OFFICIAL_REPO=1` იყენებს QGIS-ის ოფიციალურ, უფრო ახალ პაკეტებს.
ეს ცვლადები წერია ფაილში `native/stack.env`.

შემდეგ გამოიყენე ეს ფაილი: `gisstack deploy -c stack.json ...` ან გახსენი ვებ GUI-ში შენახულ პროექტად ([იხ. 8](#8-პროექტების-შენახვა-ცალკე-პროგრამის-გამოყენება-გასუფთავება)).

## 6. სად გაეშვას: ZIP, ეს მანქანა, SSH

სექცია 7, ველი **„სად"**:

| არჩევანი | რას აკეთებს |
|---|---|
| **მხოლოდ ZIP (არ გავუშვა)** | ჩამოტვირთავ დაგენერირებულ ფაილებს; მერე თავად გაუშვებ (`install.sh`, `up.sh`, `apply.sh`) |
| **ამ მანქანაზე** | GUI-ს მანქანაზე ამუშავებს. native-ისთვის GUI უნდა გეშვას **root**-ით (`sudo gisstack web`) |
| **SSH-ით სხვა სერვერზე** | ტვირთავს ფაილებს და უშვებს დისტანციურად. მიუთითე Host, Port, User და **Key** (გზა კერძო გასაღებზე ამ მანქანაზე) |

SSH-ით დაყენებისას:
- მომხმარებელი `root` ან `sudo` **პაროლის გარეშე** (`sudo -n`);
- გასაღები უკვე უნდა იყოს დაშვებული სერვერზე (`ssh-copy-id`); პაროლს GUI არ ითხოვს.

„რომელი გავუშვა" ირჩევს სამიზნეს: **native** (პაკეტები და systemd), **compose** (Docker / Podman), **k8s** (Kubernetes).

## 7. დაყენების შემდეგ: დიაგნოსტიკა და მართვა

სექცია **„9. დიაგნოსტიკა"** იყენებს იმავე სამიზნეს და „სად"-ს. დააჭირე **„განახლება"**, ან ჩართე ☑ **„ცოცხლად"**
(ახლდება ყოველ 5 წამში).

ცხრილში თითოეულ პროგრამაზე ჩანს:

| სვეტი | მნიშვნელობა |
|---|---|
| სტატუსი | `running` მუშაობს, `stopped` გაჩერებულია, `failed` ჩავარდა, `starting` იწყებს, `missing` არ არის დაყენებული |
| auto | ჩაირთვება თუ არა სერვერის გადატვირთვისას (ჩექბოქსით ცვლი) |
| PID | პროცესის ნომერი (native) |
| IP:პორტი | **რომელ მისამართსა და პორტზე უსმენს** (მაგ. `127.0.0.1:8080` = მხოლოდ ლოკალურად, `0.0.0.0:443` = გარედანაც) |
| შემოწმება | ✔ / ✘ რეალური პასუხი: TCP, პირდაპირ პროგრამის HTTP და **საჯარო ბმული Caddy-ს გავლით** |
| ბმული | გასახსნელი მისამართი (GeoServer, MapProxy, QGIS, რუკა) |

ღილაკები ყოველ რიგში: **▶** გაშვება, **■** გაჩერება, **↻** რესტარტი, **ლოგი** (ბოლო სტრიქონები),
**ცოცხლად** (ლოგი რეალურ დროში; „⏹ ლოგის შეჩერება" ბოლოში). ქვემოთ — „ყველას გაშვება / რესტარტი / გაჩერება".

ხშირი სურათები:
- `running`, მაგრამ `✘ public 502`: პროგრამა მუშაობს, Caddy ვერ აღწევს მას. შეამოწმე პორტი და ლოგი.
- `✔ public 500` QGIS Server-ზე — ნორმალურია, სანამ QGIS პროექტი (`MAP=`) არ მიგითითებია.
- GeoServer-ს პირველი გაშვება რამდენიმე წუთი სჭირდება; ამ დროს `starting`/✘, მერე ✔.

## 8. პროექტების შენახვა, ცალკე პროგრამის გამოყენება, გასუფთავება

**პროექტების შენახვა.** სექცია 1-ის ბოლოს „შენახული პროექტები": **„მთელი პროექტის შენახვა"** წერს ყველა პარამეტრს
`~/.gisstack/projects/<პროექტი>.json`-ში; **„ჩატვირთვა"** აბრუნებს მათ ფორმაში. გენერირებული პაროლები ცალკე ინახება და
ხელახალ გაშვებაზე იგივე რჩება.

**ერთი პროგრამის განახლება.** თითოეული პროგრამის პანელის ბოლოს არის ზოლი: ☑ **ჩართულია** · **შენახვა** (წერს მხოლოდ ამ
პროგრამის პარამეტრებს) · **შენახვა და გამოყენება** (ააყენებს ან გადატვირთავს მხოლოდ მას, დანარჩენს არ ეხება).
მაგალითად: შეცვალე MapProxy-ის workers და დააჭირე „შენახვა და გამოყენება": Tomcat და Caddy ხელუხლებელია.

**გასუფთავება (სექცია 8).**

| რა | შედეგი |
|---|---|
| პროგრამის გვერდით **„გასუფთავება"** | შლის მხოლოდ მას (სერვისს, ფაილებს); მონაცემები რჩება |
| **„მთელი სტეკის გასუფთავება"** | შლის ყველა პროგრამას |
| ☑ **„მონაცემების წაშლაც"** | შლის ბაზასაც, GeoServer-ის მონაცემებს, ქეშებს, volume-ებს (**ვერ აღდგება**) |
| ☑ **„PostgreSQL სერვერის პაკეტების წაშლაც"** | შლის PostgreSQL-საც (უარს იტყვის, თუ იქ სხვა ბაზებიც არის) |

Kubernetes-ზე მთელი სტეკის გასუფთავება შლის namespace-ს, ანუ ყველა volume-საც.

## 9. იგივე ბრძანების ხაზიდან

```bash
gisstack defaults > stack.json                     # კონფიგურაცია; შეცვალე ველები
gisstack generate -c stack.json -o ./bundle        # მხოლოდ ფაილების გენერაცია
gisstack deploy   -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519

gisstack status   -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519 --watch
gisstack restart  -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519 geoserver
gisstack logs     -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519 caddy -f

gisstack apply    -c stack.json mapproxy --save    # მხოლოდ ერთი პროგრამის გამოყენება
gisstack clean    -c stack.json --only tomcat      # ერთი პროგრამის გასუფთავება
gisstack clean    -c stack.json --purge -y         # მთელი სტეკი + მონაცემები
```

`--mode local` (ნაგულისხმევი) მუშაობს ამ მანქანაზე; `--mode ssh` — სხვა სერვერზე. სრული სია: `gisstack --help`.

რჩევა: ვებ GUI-ში შენახული პროექტის ფაილი (`~/.gisstack/projects/<სახელი>.json`) ჩვეულებრივი კონფიგურაციაა და `-c`-ით პირდაპირ გამოდგება.

## 10. პრობლემები და გამოსავალი

| სიმპტომი | მიზეზი და გამოსავალი |
|---|---|
| ბრაუზერში **401 token required** | გახსენი ბმული `?token=…`-ით, ან token აიღე `web.token` ფაილიდან |
| `Address already in use` | პორტი დაკავებულია: `gisstack web --port 9000` |
| `Flask` / `ModuleNotFoundError` | `./install.sh` თავიდან გაუშვი (ის აყენებს დამოკიდებულებებს) ან `pip install flask jinja2 pyyaml` |
| „native ინსტალაციას root სჭირდება" | GUI გაუშვი `sudo gisstack web`-ით, ან აირჩიე „SSH" |
| SSH: `Permission denied` | გასაღები არ არის დაშვებული სერვერზე (`ssh-copy-id`), ან User არასწორია |
| SSH: `sudo: a password is required` | მომხმარებელს სჭირდება `sudo` პაროლის გარეშე, ან გამოიყენე `root` |
| Deploy დგას GeoServer-ზე | პირველი გაშვება რამდენიმე წუთს გრძელდება; ნახე „ლოგი ცოცხლად" |
| ბრაუზერი HTTPS-ზე ამბობს „არასანდო" | `internal` რეჟიმში ნორმალურია (Caddy-ს შიდა სერტიფიკატი); რეალური დომენისთვის აირჩიე „ავტომატური" |
| `public 502` ცხრილში | პროგრამა დაეცა ან პორტი სხვაა: ნახე ამ პროგრამის „ლოგი" |
| გადატვირთვის შემდეგ პროგრამა არ ჩაირთო | დიაგნოსტიკაში ჩართე „auto" ჩექბოქსი |
