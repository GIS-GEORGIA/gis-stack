## 1. რა მჭირდება

| რა | შენიშვნა |
|---|---|
| Linux (Debian/Ubuntu ან RHEL/Rocky/Alma/Fedora) | გამოცდილია: **Ubuntu 24.04**, **Rocky 9** |
| Python 3.9+ და `python3-venv` | `install.sh` თვითონ დააყენებს, თუ აკლია |
| რეალურ სერვერზე დაყენებისთვის | `root` ან მომხმარებელი პაროლის გარეშე `sudo`-თი (SSH-ით დაყენებისას) |
| Docker / Podman ან kubectl | მხოლოდ Compose / Kubernetes სამიზნეებისთვის |
| ინტერნეტი სერვერზე | პაკეტების, Tomcat-ის, GeoServer-ის და Caddy-ს ჩამოსატვირთად |

გირჩევთ პირველად სატესტო სერვერზე ან VM-ზე გაუშვათ.

## 2. პროგრამის დაყენება და გაშვება

```bash
git clone https://github.com/GIS-GEORGIA/gis-stack.git
cd gis-stack
sudo ./install.sh          # ყველასთვის: /usr/local/bin/gisstack
# ან: ./install.sh         # მხოლოდ შენთვის: ~/.local/bin/gisstack
# ან: ./install.sh --tk    # + Desktop GUI (ინსტალერი დააყენებს python3-tk-ს)
```

შემოწმება:

```bash
gisstack --version
```

გაშვების სამი გზა:

| ბრძანება | რა არის |
|---|---|
| `gisstack web` | **ვებ GUI** (ბრაუზერში) — რეკომენდებულია |
| `gisstack desktop` | Desktop GUI (Tkinter; საჭიროა `python3-tk`) |
| `gisstack ...` | ბრძანების ხაზი, GUI-ს გარეშე ([იხ. 9](#9-იგივე-ბრძანების-ხაზიდან)) |

> **Desktop GUI და Tkinter.** `gisstack desktop` სჭირდება სისტემური პაკეტი `python3-tk` (Debian/Ubuntu) ან `python3-tkinter` (RHEL/Rocky/Fedora). თუ ის არ არის,
> პროგრამა **გეკითხება**: აჩვენებს პაკეტს და ზუსტ ბრძანებას (`sudo apt-get install -y python3-tk`) და „დავაყენო ახლავე? [y/N]“. **y**-ზე დააყენებს (sudo-ს პაროლს
> ითხოვს, თუ root არ ხარ), **n**-ზე არაფერს შეცვლის და ვებ GUI-ს შემოგთავაზებს. იგივე კითხვას `./install.sh` სვამს ტერმინალში. ხელით:
> `./install.sh --tk` დააყენებს კითხვის გარეშე, `./install.sh --no-tk` კითხვას გამოტოვებს. სერვერზე გრაფიკული ეკრანის გარეშე გამოიყენე ვებ GUI.

> თუ `gisstack` ვერ მოიძებნა და `~/.local/bin`-ში დააყენე, დაამატე იგი `PATH`-ში:
> `export PATH="$HOME/.local/bin:$PATH"`.

ან `.deb` / `.rpm` პაკეტით: `packaging/build.sh deb` (ან `rpm`), შემდეგ `sudo apt install ./dist/gisstack-installer_*_all.deb`.

## 3. ვებ GUI-ის გახსნა

```bash
gisstack web
```

ტერმინალი დაბეჭდავს მსგავს ბმულს:

```
gisstack web installer 0.1.7
  open:  http://127.0.0.1:8765/?token=AbCd...
```

გახსენი ეს **სრული ბმული** (token-ით) ბრაუზერში. token დაცვაა: მის გარეშე გვერდი 401-ს აბრუნებს.

- ვებ GUI მხოლოდ `127.0.0.1:8765`-ზე უსმენს, ანუ გარედან მიუწვდომელია. სხვა პორტი: `gisstack web --port 9000`.
- token ინახება `~/.gisstack/web.token`-ში (root-ით გაშვებისას — `/root/.gisstack/web.token`, პაკეტით დაყენებისას — `/var/lib/gisstack-installer/web.token`).
- **GUI სერვერზე გაქვს, ბრაუზერი — შენს კომპიუტერზე?** გახსენი SSH გვირაბი შენს კომპიუტერზე:

  ```bash
  ssh -L 8765:127.0.0.1:8765 user@server
  ```

  შემდეგ ბრაუზერში გახსენი იგივე `http://127.0.0.1:8765/?token=…` ბმული.
- გასაჩერებლად ტერმინალში დააჭირე `Ctrl+C`.

## 4. ნაბიჯ-ნაბიჯ: სტეკის დაყენება ვებ GUI-დან

გვერდზე სექციები არის ზემოდან ქვემოთ. ძირითადი გზა:

1. **„1. ზოგადი"**: პროექტის სახელი (a-z, 0-9, `_`), **დომენი** და HTTPS რეჟიმი (იხ. [ცხრილი](#https-რეჟიმი)).
2. **„2. კომპონენტები"**: მონიშნე რა გინდა (PostGIS, Tomcat, GeoServer, QGIS Server, MapProxy, Caddy, ვებ რუკა, მობილური შაბლონები).
3. **სექციები 3–6**: თითოეული მონიშნული პროგრამის პარამეტრები და ვერსიები ([იხ. 5](#5-პროგრამებისა-და-ვერსიების-არჩევა)).
4. **„7. სამიზნე და Deploy"**: აირჩიე *რა დაგენერირდეს* (native / Compose / Kubernetes), *რომელი გავუშვა* და *სად* ([იხ. 6](#6-სად-გაეშვას-zip-ეს-მანქანა-ssh)).
5. დააჭირე **„წინასწარი ნახვა"**: მარჯვნივ ჩანს გენერირებული ფაილები (პაროლები დაფარულია). ეს არაფერს ააყენებს.
6. დააჭირე **Deploy**, დაადასტურე. მარჯვენა ლოგში მიმდინარეობა ჩანს; ბოლოს **✔ დასრულდა**.
7. გადადი სექციაზე **„9. დიაგნოსტიკა"** და დააჭირე „განახლება": უნდა ნახო ყველა პროგრამა `running` სტატუსით და ✔ შემოწმებებით.

პაროლები ავტომატურად გენერირდება, თუ ველს ცარიელს დატოვებ. სად ინახება: native — სერვერზე `/etc/gisstack/credentials.txt`
(root-ით წასაკითხი); Compose — `compose/.env`, Kubernetes — `k8s/secret.yaml` დაგენერირებულ ბანდლში
(GUI-დან გაშვებისას ის `~/.gisstack/bundles/<პროექტი>-…/` საქაღალდეშია).

### HTTPS რეჟიმი

| არჩევანი | როდის |
|---|---|
| **ავტომატური Let's Encrypt** | რეალური დომენი, რომელიც სერვერზე მიუთითებს; ველში ჩაწერე ელ-ფოსტა; პორტები 80 და 443 ღია |
| **Caddy-ს შიდა CA** | `localhost`, ინტრანეტი, ტესტი; ბრაუზერი გაფრთხილებას აჩვენებს (სერტიფიკატი არ არის სანდო) |
| **HTTP მხოლოდ** | TLS-ის გარეშე (მხოლოდ დახურულ ქსელში) |

> `localhost`-ისთვის „ავტომატური" არ მუშაობს — GUI ამას შეგატყობინებს.

## 5. პროგრამებისა და ვერსიების არჩევა

### კომპონენტები (სექცია 2)

| კომპონენტი | რას აკეთებს |
|---|---|
| PostgreSQL + PostGIS | სივრცითი ბაზა |
| Apache Tomcat | Java კონტეინერი (GeoServer-ისთვის **ავტომატურად** ემატება native-ზე) |
| GeoServer | WMS / WFS / WMTS |
| QGIS Server | QGIS პროექტების გამოქვეყნება |
| MapProxy | ტაილების ქეში, WMTS, seed |
| Caddy | ერთი შესასვლელი `/`, `/geoserver`, `/mapproxy`, `/qgis` + HTTPS |
| ვებ რუკა | ორენოვანი (KA/EN) Leaflet რუკა, უკვე მიბმული შენს ფენებზე |
| მობილური რუკები | React Native და Flutter შაბლონები (ფაილებად, არ ინსტალირდება) |

### რომელი ვერსიის არჩევა შეიძლება ვებ GUI-ში

| რა | სად | არჩევანი |
|---|---|---|
| **PostgreSQL** | სექცია 3, „ვერსია" | 18, 17, 16, 15, 14 (გამოცდილია **17**) |
| **GeoServer** | სექცია 4, „GeoServer ხაზი" | **3.0** (3.0.2, სტაბილური) ან **2.28** (2.28.6, მხარდაჭერილი) |

GeoServer 3.0 არ მუშაობს Tomcat 10.1-ზე; GUI ამას ზუსტად ამიტომ არ გაძლევს ამ კომბინაციას. სექცია 4-ში ირჩევ ხაზს და ქვემოთ წერს,
რომელი Tomcat და Java გამოიყენება.

### დამატებითი არჩევანი

| სექცია | რა |
|---|---|
| 3. PostgreSQL | ექსთენშენები მონიშვნით (PostGIS raster/topology, pgRouting, pointcloud, ogr_fdw, H3, hstore, pg_trgm, ...), RAM (GB) ტიუნინგისთვის, `max_connections`, გარე წვდომა + დაშვებული CIDR |

| 5. MapProxy | ქეშის ტიპი (file / sqlite / geopackage), ფორმატი, workers, ფონი (არცერთი / OSM), **grid-ები** (3857, 4326, UTM 38N/37N), ფენები (სახელი, სათაური KA/EN, წყარო, WMS ფენა), წინასწარი seed |

### რაც მხოლოდ კონფიგურაციის ფაილშია (GUI-ში არ ჩანს)

ზუსტი პატჩ-ვერსია, საკუთარი image, პორტები და სხვა ხელით იწერება კონფიგურაციაში:

```bash
gisstack defaults > stack.json      # ნაგულისხმევი კონფიგურაცია, შეცვალე ველები
```

| ველი `stack.json`-ში | რას ცვლის |
|---|---|
| `geoserver.version` | ზუსტი GeoServer ვერსია (ცარიელი = არჩეული ხაზის ნაგულისხმევი) |
| `geoserver.image` | GeoServer-ის Docker image (Compose / k8s) |
| `tomcat.major` (`11`, `10.1`, `9`) | მხოლოდ **GeoServer-ის გარეშე** დაყენებულ Tomcat-ზე |
| `tomcat.port` | Tomcat-ის პორტი (ნაგულისხმევი 8080) |
| `k8s.postgis_image`, `k8s.mapproxy_image` | საკუთარი image-ები Kubernetes-ზე |
| `runtime` | `docker` ან `podman` |

**ხელით გაშვებისას** (ZIP-ით ან `gisstack generate`-ით მიღებული `native/install.sh`) ზოგიერთი ვერსია გარემოდანაც იცვლება:
`cd native && sudo TOMCAT_VERSION=11.0.20 JAVA_VERSION=21 ./install.sh`; `QGIS_OFFICIAL_REPO=1` იყენებს QGIS-ის ოფიციალურ, უფრო ახალ პაკეტებს.
ეს ცვლადები წერია ფაილში `native/stack.env`.

შემდეგ გამოიყენე ეს ფაილი: `gisstack deploy -c stack.json ...` ან გახსენი ვებ GUI-ში შენახულ პროექტად ([იხ. 8](#8-პროექტების-შენახვა-ცალკე-პროგრამის-გამოყენება-გასუფთავება)).

## 6. სად გაეშვას: ZIP, ეს მანქანა, SSH

სექცია 7, ველი **„სად"**:

| არჩევანი | რას აკეთებს |
|---|---|
| **მხოლოდ ZIP (არ გავუშვა)** | ჩამოტვირთავ დაგენერირებულ ფაილებს; მერე თავად გაუშვებ (`install.sh`, `up.sh`, `apply.sh`) |
| **ამ მანქანაზე** | GUI-ს მანქანაზე ამუშავებს. native-ისთვის GUI უნდა გეშვას **root**-ით (`sudo gisstack web`) |
| **SSH-ით სხვა სერვერზე** | ტვირთავს ფაილებს და უშვებს დისტანციურად. მიუთითე Host, Port, User და **Key** (გზა კერძო გასაღებზე ამ მანქანაზე) |

SSH-ით დაყენებისას:
- მომხმარებელი `root` ან `sudo` **პაროლის გარეშე** (`sudo -n`);
- გასაღები უკვე უნდა იყოს დაშვებული სერვერზე (`ssh-copy-id`); პაროლს GUI არ ითხოვს.

„რომელი გავუშვა" ირჩევს სამიზნეს: **native** (პაკეტები და systemd), **compose** (Docker / Podman), **k8s** (Kubernetes).

## 7. დაყენების შემდეგ: დიაგნოსტიკა და მართვა

სექცია **„9. დიაგნოსტიკა"** იყენებს იმავე სამიზნეს და „სად"-ს. დააჭირე **„განახლება"**, ან ჩართე ☑ **„ცოცხლად"**
(ახლდება ყოველ 5 წამში).

ცხრილში თითოეულ პროგრამაზე ჩანს:

| სვეტი | მნიშვნელობა |
|---|---|
| სტატუსი | `running` მუშაობს, `stopped` გაჩერებულია, `failed` ჩავარდა, `starting` იწყებს, `missing` არ არის დაყენებული |
| auto | ჩაირთვება თუ არა სერვერის გადატვირთვისას (ჩექბოქსით ცვლი) |
| PID | პროცესის ნომერი (native) |
| IP:პორტი | **რომელ მისამართსა და პორტზე უსმენს** (მაგ. `127.0.0.1:8080` = მხოლოდ ლოკალურად, `0.0.0.0:443` = გარედანაც) |
| შემოწმება | ✔ / ✘ რეალური პასუხი: TCP, პირდაპირ პროგრამის HTTP და **საჯარო ბმული Caddy-ს გავლით** |
| ბმული | გასახსნელი მისამართი (GeoServer, MapProxy, QGIS, რუკა) |

ღილაკები ყოველ რიგში: **▶** გაშვება, **■** გაჩერება, **↻** რესტარტი, **ლოგი** (ბოლო სტრიქონები),
**ცოცხლად** (ლოგი რეალურ დროში; „⏹ ლოგის შეჩერება" ბოლოში). ქვემოთ — „ყველას გაშვება / რესტარტი / გაჩერება".

ხშირი სურათები:
- `running`, მაგრამ `✘ public 502`: პროგრამა მუშაობს, Caddy ვერ აღწევს მას. შეამოწმე პორტი და ლოგი.
- `✔ public 500` QGIS Server-ზე — ნორმალურია, სანამ QGIS პროექტი (`MAP=`) არ მიგითითებია.
- GeoServer-ს პირველი გაშვება რამდენიმე წუთი სჭირდება; ამ დროს `starting`/✘, მერე ✔.

## 8. პროექტების შენახვა, ცალკე პროგრამის გამოყენება, გასუფთავება

**პროექტების შენახვა.** სექცია 1-ის ბოლოს „შენახული პროექტები": **„მთელი პროექტის შენახვა"** წერს ყველა პარამეტრს
`~/.gisstack/projects/<პროექტი>.json`-ში; **„ჩატვირთვა"** აბრუნებს მათ ფორმაში. გენერირებული პაროლები ცალკე ინახება და
ხელახალ გაშვებაზე იგივე რჩება.

**ერთი პროგრამის განახლება.** თითოეული პროგრამის პანელის ბოლოს არის ზოლი: ☑ **ჩართულია** · **შენახვა** (წერს მხოლოდ ამ
პროგრამის პარამეტრებს) · **შენახვა და გამოყენება** (ააყენებს ან გადატვირთავს მხოლოდ მას, დანარჩენს არ ეხება).
მაგალითად: შეცვალე MapProxy-ის workers და დააჭირე „შენახვა და გამოყენება": Tomcat და Caddy ხელუხლებელია.

**გასუფთავება (სექცია 8).**

| რა | შედეგი |
|---|---|
| პროგრამის გვერდით **„გასუფთავება"** | შლის მხოლოდ მას (სერვისს, ფაილებს); მონაცემები რჩება |
| **„მთელი სტეკის გასუფთავება"** | შლის ყველა პროგრამას |
| ☑ **„მონაცემების წაშლაც"** | შლის ბაზასაც, GeoServer-ის მონაცემებს, ქეშებს, volume-ებს (**ვერ აღდგება**) |
| ☑ **„PostgreSQL სერვერის პაკეტების წაშლაც"** | შლის PostgreSQL-საც (უარს იტყვის, თუ იქ სხვა ბაზებიც არის) |

Kubernetes-ზე მთელი სტეკის გასუფთავება შლის namespace-ს, ანუ ყველა volume-საც.

## 9. იგივე ბრძანების ხაზიდან

```bash
gisstack defaults > stack.json                     # კონფიგურაცია; შეცვალე ველები
gisstack generate -c stack.json -o ./bundle        # მხოლოდ ფაილების გენერაცია
gisstack deploy   -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519

gisstack status   -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519 --watch
gisstack restart  -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519 geoserver
gisstack logs     -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519 caddy -f

gisstack apply    -c stack.json mapproxy --save    # მხოლოდ ერთი პროგრამის გამოყენება
gisstack clean    -c stack.json --only tomcat      # ერთი პროგრამის გასუფთავება
gisstack clean    -c stack.json --purge -y         # მთელი სტეკი + მონაცემები
```

`--mode local` (ნაგულისხმევი) მუშაობს ამ მანქანაზე; `--mode ssh` — სხვა სერვერზე. სრული სია: `gisstack --help`.

რჩევა: ვებ GUI-ში შენახული პროექტის ფაილი (`~/.gisstack/projects/<სახელი>.json`) ჩვეულებრივი კონფიგურაციაა და `-c`-ით პირდაპირ გამოდგება.

### წინასწარი შემოწმება, პაროლების შეცვლა, ჟურნალი

```bash
gisstack preflight --mode ssh --ssh user@server          # OS, მეხსიერება, დისკი, საათი, ქსელი (deploy-ზეც ავტომატურად; --skip-preflight)
gisstack rotate-credentials postgres --mode ssh --ssh user@server    # ახალი პაროლი (გენერირდება), გადამოწმდება, მერე ჩაიწერება
gisstack rotate-credentials geoserver --password-file ~/new.pw       # საკუთარი პაროლი ფაილიდან (chmod 600)
```

პაროლები კონფიგურაციის ფაილის გარეშეც შეიძლება: `GISSTACK_POSTGRES_PASSWORD`, `GISSTACK_GEOSERVER_ADMIN_PASSWORD` ან იგივე `_FILE` სუფიქსით.
ოპერაციების ჟურნალი: `~/.gisstack/journal.jsonl`; ვებ GUI-ის აუდიტი: `~/.gisstack/audit.log`. გრძელი ოპერაციის ვადა: `GISSTACK_DEADLINE` (წამი, ნაგულისხმევი 3600),
უმოქმედობის ლიმიტი: `GISSTACK_IDLE_TIMEOUT` (900); `0` — ლიმიტის გარეშე.

ვებ GUI: `gisstack web --allow-host gis.example.ge` (სხვა Host სახელი), `--rotate-token` (ახალი წვდომის ტოკენი), `--server auto|waitress|werkzeug` (ნაგულისხმევი `auto`: waitress, თუ დაყენებულია, სხვაგვარად Flask-ის სატესტო სერვერი გაფრთხილებით). წვდომის ტოკენი ეკრანზე მხოლოდ ტერმინალში იწერება (`GISSTACK_PRINT_TOKEN=1` — ყოველთვის); სერვისი არ ბეჭდავს მას ჟურნალში.

### ვებ დაფა (feature flag)


აღწერა: [DASHBOARD.md](DASHBOARD.md).

### მონიტორინგი (feature flag)

```bash
export GISSTACK_FEATURES=monitoring
gisstack monitor collect --mode ssh --ssh root@server     # რეალური ნიმუში: CPU, მეხსიერება, დისკი, სერვისები, PostgreSQL, health checks
gisstack monitor watch   --mode ssh --ssh root@server --interval 30
```

ალერტები, webhook/e-mail და API: [MONITORING.md](MONITORING.md). Feature flag-ები: `GISSTACK_FEATURES=monitoring,prometheus` (ან `all`).

### ბექაფი და აღდგენა (native)

```bash
gisstack backup create --mode ssh --ssh root@server --download ~/backups     # დადასტურებული ბექაფი + ასლი ამ კომპიუტერზე
gisstack backup list   --mode ssh --ssh root@server
gisstack backup restore ID --mode ssh --ssh root@server                      # ჯერ გეგმას აჩვენებს, ეკითხება, ავტომატურად ბექაფობს, საჭიროების შემთხვევაში უკან აბრუნებს
gisstack backup schedule enable --calendar daily --keep 14 --days 30        # ავტომატური ბექაფი (systemd timer)
```

სრული აღწერა, retention, ავარიული აღდგენა ახალ სერვერზე: [RECOVERY.md](RECOVERY.md). ბექაფი პაროლებს შეიცავს — დაიცავი.

### ქსელი, კონტეინერების დაცვა და HTTPS პროქსი (კონფიგურაციის ფაილში)

| გასაღები | მნიშვნელობა |
|---|---|
| `network.bind` | ჰოსტის მისამართი იმ პორტებისთვის, რომლებიც **Caddy-ს გარეშე** იხსნება (GeoServer 8080, MapProxy 8081, QGIS 8380, Tomcat). ნაგულისხმევი `127.0.0.1` (მხოლოდ ეს მანქანა); `0.0.0.0` = ყველა ინტერფეისი (Docker firewall-ს გვერდს უვლის!) — მხოლოდ შეგნებული არჩევანია. `schema_version: 1` ფაილებს ძველი ქცევა ცხადად ჩაეწერებათ (`0.0.0.0`) გაფრთხილებით; ახალი/ხელნაწერი კონფიგი იღებს `127.0.0.1`-ს. ყველა საჯარო წვდომა Caddy-ს გავლით უნდა იყოს. PostgreSQL ისევ `postgres.remote_access`-ით იმართება |
| `security.harden_containers` | ნაგულისხმევი `true`: ყველა კონტეინერი კარგავს ყველა Linux capability-ს და `no-new-privileges`-ს იღებს (Kubernetes: `allowPrivilegeEscalation: false`, `drop: [ALL]`, seccomp `RuntimeDefault`); იმ image-ს, რომელსაც მეტი სჭირდება, უბრუნდება მხოლოდ საჭირო (PostGIS: CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETUID; QGIS: CHOWN, SETGID, SETUID; Caddy: NET_BIND_SERVICE). საკუთარი image-ებისთვის `false` ცვლის ყველაფერს უკან. read-only root FS და რესურსის ლიმიტები **არ** არის დამატებული |
| `GISSTACK_TRUSTED_PROXIES` (გარემოს ცვლადი ვებ სერვისზე) | მძიმით გამოყოფილი მისამართები, რომელთა `X-Forwarded-Proto: https` დაიჯერება: მხოლოდ მაშინ ეძლევა სესიის cookie-ს `Secure`. ნაგულისხმევად ცარიელია: კლიენტის გამოგზავნილ სათაურს არავინ არ ენდობა. პირდაპირი http (ან SSH ტუნელი) loopback-ზე უცვლელად მუშაობს (cookie `HttpOnly; SameSite=Strict`, `Secure`-ს გარეშე) |

Caddy-ს HTTP/HTTPS პორტები `.env`-ში (`HTTP_PORT`, `HTTPS_PORT`) შეგიძლია შეცვალო: gis-stack-ის ჯანმრთელობის შემოწმება რეალურ გამოქვეყნებულ პორტს ძრავიდან კითხულობს. სურათზე მიმაგრებული ბმული (`https://დომენი/`) პორტს არ შეიცავს.

### ბექაფის დაშიფვრა — როდის არის აუცილებელი

Caddy-ს ბექაფი შეიცავს TLS პირად გასაღებებს და ACME ანგარიშს, GeoServer-ისა — მომხმარებლების ჰაშებს. ფაილები 0600/0700-ია და არსად ლოგირდება, მაგრამ **დაუშიფრავია, თუ `--encrypt`/`--encrypt-to` არ გამოიყენე**. დაშიფრე ყოველი ასლი, რომელიც მანქანას ტოვებს (offsite, გარე დისკი, ღრუბელი) და ნებისმიერი ასლი, რომელსაც Caddy ან GeoServer შეიცავს; გასაღები/პაროლი ბექაფთან ერთად არ შეინახო (დაკარგვის შემთხვევაში აღდგენა შეუძლებელია).

### Podman (rootless): სესიის დასრულება და გადატვირთვა

Rootless Podman-ს დემონი არ აქვს: კონტეინერები მომხმარებლის systemd-ში ცხოვრობს. გადამოწმებულია რეალურ Podman-ზე:

- პროცესის ავარია (`restart: unless-stopped`) → კონტეინერი თავისით ამოდის; `gisstack stop/start/restart` მუშაობს ნებისმიერი საქაღალდიდან.
- **ბოლო სესიის დასრულებისას** (`lingering` გამორთულია) კონტეინერები ჩერდება. გამოსავალი: `loginctl enable-linger $USER`.
- **სერვერის გადატვირთვის შემდეგ** კონტეინერები თავისით **არ** ამოდის, სანამ არ ჩართავ: `systemctl --user enable podman-restart.service` (lingering-თან ერთად).
- `gisstack preflight` ორივე შემთხვევაზე გაფრთხილებას გაჩვენებს (ბლოკი არ არის). ეს ბრძანებები სისტემას **შენ** ცვლი — gis-stack მათ თავისით არ ასრულებს.
- თუ `podman compose` Docker Compose პროვაიდერს იყენებს, საჭიროა Podman-ის სოკეტი (`systemctl --user enable --now podman.socket`) ან `PODMAN_COMPOSE_PROVIDER=podman-compose`; gis-stack პროვაიდერს თავისით არ ცვლის და გასაგებ შეცდომას აჩვენებს.

როცა ახალი ვერსია გამოდის GitHub-ზე, პროგრამა არ გაწუხებს თავისით; განახლებას **შენ** ამოწმებ:

- **ვებ GUI:** ზედა მარჯვენა კუთხეში **„განახლების შემოწმება“**. გამოჩნდება ახალი ვერსია, ცვლილებების ტექსტი და ჩამოსატვირთი
  ფაილები. თუ პროგრამა `install.sh`-ით გაქვს დაყენებული, ჩნდება **„განახლება ახლავე“**: ჩამოტვირთავს, გადაამოწმებს SHA-256-ს და
  ჩაანაცვლებს ფაილებს. მერე გადატვირთე `gisstack web`.
- **Desktop GUI:** ღილაკი **„განახლების შემოწმება“** ზედა ზოლში.
- **ბრძანების ხაზი:**
  ```bash
  gisstack update --check              # მხოლოდ შემოწმება (კოდი 10 = ახალი ვერსია არსებობს)
  gisstack update                      # შეამოწმებს და (venv-ში) განაახლებს
  gisstack update --download ~/Downloads   # ჩამოტვირთავს .deb/.rpm/.tar.gz-ს, SHA-256-ით გადამოწმებულს
  ```

| როგორ გაქვს დაყენებული | რა მოხდება |
|---|---|
| `./install.sh` (venv) | ავტომატური განახლება |
| `.deb` / `.rpm` პაკეტი | ჩამოტვირთე ახალი პაკეტი და დააყენე: `sudo apt install ./ფაილი` / `sudo dnf install ./ფაილი` |
| `git clone` | `git pull` |

განახლება არ ეხება უკვე დაყენებულ GIS სერვერს: ის მხოლოდ ამ ინსტალერის პროგრამას ანახლებს. თუ ახალი ვერსია სერვერზე ახალ
კონფიგურაციას ითხოვს, დააჭირე Deploy ან „შენახვა და გამოყენება“ იმ პროგრამაზე.

### პაკეტით დაყენებული ვებ სერვისის განახლება (≤ 0.1.7 → ახალი)

გადამოწმებულია Ubuntu 24.04-ზე (წინა გამოშვების `.deb` → ახალი `.deb`, წარუმატებელი განახლება, უკან დაბრუნება):

```bash
sudo apt install ./gisstack-installer_<ახალი>_all.deb      # ან dnf install ./...rpm
sudo systemctl daemon-reload && sudo systemctl restart gisstack-web
```

- კონფიგურაცია, ტოკენი, პროექტები და საიდუმლოებები უცვლელი რჩება; სერვისი ახლა **უპრივილეგიოდ** მუშაობს (`DynamicUser`), ფაილები მის მფლობელობაში გადადის (რეჟიმები 0700/0600 იგივე რჩება). ადგილობრივი ინსტალაციისთვის root-ის სერვისი ცალკეა: `gisstack-web-root.service`.
- დაზიანებული/შეწყვეტილი პაკეტი მოქმედ ინსტალაციას არ აზიანებს (ძველი ვერსია და გაშვებული სერვისი რჩება). უკან დაბრუნება: წინა პაკეტის ხელახალი დაყენება (`dpkg -i` / `dnf downgrade`) — სერვისი ისევ root-ით გაეშვება და იგივე მონაცემებს კითხულობს.
- **ტოკენი თავისით იცვლება (ერთხელ):** ვერსიები ≤ 0.1.7 ტოკენს systemd-ის ჟურნალში ბეჭდავდნენ. ახალი პაკეტი განახლებისას ძველ `web.token`-ს შლის, სერვისს თავად გადატვირთავს (მეხსიერებაში დარჩენილი ძველი ტოკენიც კვდება) და ახალს სერვისი თავად ქმნის (მფლობელი: სერვისის მომხმარებელი, რეჟიმი 0600; ეკრანზე/ჟურნალში არ იბეჭდება). ახალი ტოკენი: `sudo cat /var/lib/gisstack-installer/web.token`. ეს ხდება **მხოლოდ ერთხელ** (ნიშანი: `/etc/gisstack-installer/token-protected`); ჩვეულებრივი გადატვირთვა და მომდევნო განახლებები ტოკენს არ ცვლის, ახალი ინსტალაციის ტოკენიც უცვლელია. თუ ტოკენის წაშლა ვერ მოხერხდა, პაკეტი არ ვარდება და შემდეგ ჯერზე ისევ ცდის; ხელით აღდგენა/ახალი ტოკენი ნებისმიერ დროს: `sudo systemctl stop gisstack-web && sudo rm -f /var/lib/gisstack-installer/web.token && sudo systemctl start gisstack-web`. **ნუ გამოიყენებ** `gisstack web --rotate-token`-ს root-ით ამ სერვისზე: ის root-ის მფლობელობაში მყოფ ტოკენს ტოვებს, რომელსაც უპრივილეგიო სერვისი ვერ კითხულობს.
- rpm-ის განახლება ამ მანქანაზე **არ** გადამოწმებულა (`rpmbuild` არ არის); rpm-ის ახალი ინსტალაცია CI-ში გადამოწმებულია.

## 11. სერვერზე უკვე დგას პროგრამები

სანამ ჩვენს სტეკს დააყენებ, სერვერზე შეიძლება უკვე იყოს PostgreSQL, Tomcat, Caddy, nginx და სხვა. პროგრამა ამას **დაყენებამდე**
ამოწმებს და არაფერს ხელს არ ახლებს, სანამ არ გადაწყვეტ. *(მხოლოდ native სამიზნე; სერვერზე საჭიროა root ან `sudo` პაროლის გარეშე.)*

**ვებ GUI-ში:** სექცია **„7ა. არსებული პროგრამები“** → **„შემოწმება“**. ცხრილში ჩანს თითოეული ნაპოვნი პროგრამა: **ჩვენია** (gisstack-ით
დაყენებული) თუ **უცხო**, ვერსია, სერვისი და მისი სტატუსი, **IP:პორტი**, ბაზების სია და ზომა. წითელ ველში არის **პორტების კონფლიქტი**:
რომელ პორტს ვინ იკავებს (მაგ. 80-ს nginx, 8080-ს სხვა Tomcat).

**უცხო პროგრამაზე ირჩევ:**

| არჩევანი | რას აკეთებს |
|---|---|
| **დავტოვო** | არაფერს ეხება. შესაძლებელია მხოლოდ თუ ჩვენ საჭირო პორტს არ იკავებს |
| **დაშენება** (მხოლოდ PostgreSQL) | ვიყენებთ **არსებულ** PostgreSQL სერვერს: ახალს არ ვაყენებთ, პარამეტრებს არ ვცვლით, არ ვრესტარტებთ; ვამატებთ მხოლოდ ჩვენს ბაზას, როლს და PostGIS-ს. ვერსია გადმოიღება არსებულიდან |
| **წაშლა** | ჯერ ბექაფი, მერე პროგრამის წაშლა. **მონაცემები რჩება** (მაგ. ბაზის ფაილები); ჩექბოქსი „მონაცემებიც წაიშალოს“ შლის მათაც |
| **გამოყენება ჩვენში** | ბექაფი → წაშლა → ჩვენი დაყენება → **გადმოტანა ჩვენში**: PostgreSQL-ის ბაზები, GeoServer-ის workspace-ები/სტილები/ფენები, QGIS პროექტები, Caddy-ს საიტების ბლოკები |
| **გავთიშო** | nginx/apache-ისთვის: გაჩერება და ავტოგაშვების გამორთვა (პორტი 80/443 თავისუფლდება) |

გეგმას **Deploy** ავტომატურად იყენებს. ცალკე ღილაკებიც არის: **„ბექაფი (უცხო პროგრამების)“** და **„გეგმის შესრულება (დაყენების გარეშე)“**.
თუ გეგმა არ აგირჩევია და საჭირო პორტი დაკავებულია, Deploy **არ დაიწყება** და სწორედ ამ სექციას გაჩვენებს.

**ბექაფი:** სერვერზე `/var/backups/gisstack/<დრო>/`, ასლი ამ მანქანაზე `~/.gisstack/backups/<სერვერი>/<დრო>.tar.gz`. შიგნით: თითოეული პროგრამის
კონფიგურაცია (`/etc/postgresql`, `/etc/tomcat*`, `/etc/caddy`, GeoServer-ის data directory, `/srv/qgis`, ...) და, ბაზებისთვის, `pg-globals.sql`
(როლები). ბაზების **დამპი** კეთდება, როცა აირჩევ „გამოყენება ჩვენში“ ან ჩართავ „ბექაფში მონაცემებიც“.

**რა გადმოდის და რა არა (გამოყენება ჩვენში):**
- **PostgreSQL:** ყველა ბაზა (მფლობელი ხდება ჩვენი მომხმარებელი). იგივე სახელის ბაზას არ ვაგადაწერთ.
- **GeoServer:** workspace-ები, სტილები, ფენები, datastore-ები. **`security/` არ გადმოდის**: შენი ახალი admin პაროლი რჩება; ძველი
  მომხმარებლები/როლები და დაშიფრული datastore პაროლები თავიდან უნდა შეიყვანო (ძველი ინახება ბექაფში).
- **QGIS Server:** პროექტის ფაილები → ჩვენი პროექტების საქაღალდე.
- **Caddy:** ძველი Caddyfile-ის საიტების ბლოკები ჩაერთვება ჩვენსაში (`/etc/gisstack/caddy.d/imported.caddy`). თუ ჩვენსას ეჯახება, არ ჩაერთვება და
  ფაილი დარჩება `/etc/gisstack/imported/Caddyfile.foreign`-ში.
- **Tomcat, MapProxy:** ავტომატურად არაფერი გადმოდის; პარამეტრები ბექაფშია სახელმძღვანელოდ.

**უსაფრთხოების გარანტიები:** წაშლამდე ბექაფი სრულად მოწმდება (არქივები იკითხება, დამპები აღდგება, SHA-256). თუ ბექაფი ვერ შეიქმნა ან ვერ გადამოწმდა,
**არაფერი იშლება** (ჩავარდნილი ბექაფი რჩება `<id>.FAILED` სახელით). მონაცემების წაშლა (`remove+purge`) მოითხოვს დადასტურებას: GUI-ში გამაფრთხილებელ დიალოგს, CLI-ში
`--confirm-data-loss`. ბექაფის ფაილი არასოდეს გადაიწერება.

**ბრძანების ხაზიდან:**
```bash
gisstack scan -c stack.json --mode ssh --ssh user@server --key ~/.ssh/id_ed25519      # რა დგას?
gisstack existing backup tomcat caddy -c stack.json --mode ssh ... --with-data          # მხოლოდ ბექაფი
gisstack existing remove tomcat -c stack.json --mode ssh ...                           # ბექაფი + წაშლა
gisstack deploy -c stack.json --mode ssh ... \
    --existing "postgis=reuse,tomcat=remove,caddy=reuse,nginx=disable"                 # გეგმით
```
მოქმედებები: `ignore`, `adopt`, `remove`, `reuse`, `disable`; `+purge` (მაგ. `tomcat=remove+purge`) შლის მონაცემებსაც და მოითხოვს `--confirm-data-loss`-ს.
`gisstack scan` აბრუნებს კოდს 3-ს, თუ პორტების კონფლიქტია.

## 12. პარამეტრები: ენა, თემა, GitHub

ორივე GUI (ვებ და Desktop) ორენოვანია (**ქართული / English**) და აქვს **ღია / მუქი** თემა.

- **ვებ GUI:** სათაურში არის გადამრთველი **KA | EN**, თემის ღილაკი **◐** (ავტომატური → ღია → მუქი), **⚙ პარამეტრები** და **GitHub**.
  ცვლილება მაშინვე მოქმედებს, გვერდის გადატვირთვა არ სჭირდება.
- **Desktop GUI:** ზედა ზოლში **⚙ პარამეტრები** და **GitHub**. პარამეტრების ფანჯარაში ირჩევ ენას და თემას, **„შენახვა და გადატვირთვა“** კი
  პროგრამას თავიდან გახსნის ახალი პარამეტრებით.
- **ბრძანების ხაზიდან:** `gisstack settings --lang en --theme dark` (`--lang auto|ka|en`, `--theme auto|light|dark`); უპარამეტროდ აჩვენებს მიმდინარეს.

**ავტომატური** ენა იღებს სისტემის ენას (`ka_*` → ქართული, სხვა შემთხვევაში English), ავტომატური თემა — სისტემის ღია/მუქ რეჟიმს. პარამეტრები ინახება
`~/.gisstack/settings.json`-ში და ორივე GUI-სთვის საერთოა. ენა გარემოდანაც იცვლება: `GISSTACK_LANG=en gisstack web`.

შენიშვნა: ბრძანების ხაზის ტექსტები (`gisstack status` და სხვ.) ახლა ქართულადაა და ინგლისურად არ ითარგმნება.

## 13. პრობლემები და გამოსავალი

| სიმპტომი | მიზეზი და გამოსავალი |
|---|---|
| ბრაუზერში **401 token required** | გახსენი ბმული `?token=…`-ით, ან token აიღე `web.token` ფაილიდან |
| `Address already in use` | პორტი დაკავებულია: `gisstack web --port 9000` |
| `Flask` / `ModuleNotFoundError` | `./install.sh` თავიდან გაუშვი (ის აყენებს დამოკიდებულებებს) ან `pip install flask jinja2 pyyaml` |
| „native ინსტალაციას root სჭირდება" | GUI გაუშვი `sudo gisstack web`-ით, ან აირჩიე „SSH" |
| SSH: `Permission denied` | გასაღები არ არის დაშვებული სერვერზე (`ssh-copy-id`), ან User არასწორია |
| SSH: `sudo: a password is required` | მომხმარებელს სჭირდება `sudo` პაროლის გარეშე, ან გამოიყენე `root` |
| Deploy დგას GeoServer-ზე | პირველი გაშვება რამდენიმე წუთს გრძელდება; ნახე „ლოგი ცოცხლად" |
| ბრაუზერი HTTPS-ზე ამბობს „არასანდო" | `internal` რეჟიმში ნორმალურია (Caddy-ს შიდა სერტიფიკატი); რეალური დომენისთვის აირჩიე „ავტომატური" |
| `public 502` ცხრილში | პროგრამა დაეცა ან პორტი სხვაა: ნახე ამ პროგრამის „ლოგი" |
| გადატვირთვის შემდეგ პროგრამა არ ჩაირთო | დიაგნოსტიკაში ჩართე „auto" ჩექბოქსი |
| „განახლების შემოწმება“: ვერ დავუკავშირდი / ჯერ release არ არსებობს | არ არის ინტერნეტი, GitHub-ის ლიმიტი (სცადე მოგვიანებით), ან მეინტეინერმა ჯერ არ გამოუშვა ვერსია |

## API და ავტომატიზაცია (Phase 10)

```bash
gisstack token create --name ci --scope read --ttl-days 30     # ტოკენი ერთხელ ჩანს (stdout)
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8765/api/v1/meta
gisstack token list ; gisstack token revoke <id>
gisstack api docs -o docs/API.md ; gisstack api openapi -o docs/openapi.json
```

სრული მითითება: `docs/API.md` (გენერირებულია). პლაგინები: `docs/PLUGINS.md`.
