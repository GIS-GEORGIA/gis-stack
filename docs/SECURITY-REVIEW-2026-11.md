# Security and reliability review - 2026-11-10

Scope: the code at `b4213fb` plus the uncommitted fixes listed at the end. Method: reading the code, running the real suites, and targeted experiments (a real `sshd`, a real Pebble ACME server, real Docker Compose and Podman engines, systemd containers, Chromium). Every finding says how it was reproduced and which regression test pins it. "Fixed" means fixed in the working tree and covered by a test that failed before the change; nothing here is committed.

Severity scale: **High** (remote compromise or data loss without a precondition), **Medium** (needs a precondition or reduces a security control), **Low** (hardening / defence in depth), **Info** (documented trade-off).

## Reliability defects found and fixed in this review

| # | Severity | Defect | Reproduction | Fix | Test |
|---|---|---|---|---|---|
| R-1 | High (availability) | **Alert notifications were lost** when the receiver was down at the moment the alert fired (webhook/e-mail): three quick retries, then nothing, the alert stayed "firing" and was never announced (the default reminder is 6 h). The "resolved" notice was lost the same way. | real HTTP receiver, down at fire time, up later: 5 of 7 delivery tests failed | persisted outbox with back-off (60 s doubling to 30 min), ordered per provider, dropped after 24 h with a visible `notify.dropped` event, survives a monitor restart; `notify.failed` / `notify.retried` events | `tests/test_monitoring_delivery.py` |
| R-2 | High (operations) | On **Podman with `podman-compose`**, `gisstack stop/start/restart` failed with `no compose.yaml found` (exit 255) unless the current directory contained the compose file. | rootless and rootful Podman, `ops.control` from `/` | the control scripts talk to the Podman engine directly (as status, logs and enable already did); no compose provider involved | `tests/test_podman.py`, `integration/test_podman_reliability.py::PodmanLifecycle` (rootful + rootless) |
| R-3 | Medium | rootless Podman stacks stop when the user's last session ends (no lingering) and **do not come back after a reboot** unless `podman-restart.service` is enabled for the user; gis-stack neither checked nor documented this. | nested rootless engine: `terminate-user` with linger off, user-manager restart with and without `podman-restart.service` | non-blocking pre-flight warnings `podman_linger` / `podman_restart`; documentation | `tests/test_preflight.py` (+ run against the real engine) |

Positive evidence worth keeping: secrets never appeared in console output, backup logs and manifests, the operation journal, monitor history, the audit log or the systemd journal of the new release (state-directory scan); the web token comparison is constant-time; scoped tokens are rejected on legacy routes; sessions have idle and absolute expiry; CSRF header required for cookie sessions; Host-header allow-list and failure rate limit are active; every secret-bearing generated file is mode 0600.
