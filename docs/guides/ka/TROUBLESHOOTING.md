# პრობლემების გადაჭრა

ინგლისური ვერსია: [../en/TROUBLESHOOTING.md](../en/TROUBLESHOOTING.md). ჯერ ნახე, რა მუშაობს სინამდვილეში:

```bash
gisstack status -c stack.json
gisstack logs -c stack.json geoserver -n 200
```

## ვებ GUI წერს „unauthorized“-ს ან არ იხსნება

GUI მხოლოდ `127.0.0.1`-ზე უსმენს და სჭირდება token იმ ბმულიდან, რომელსაც `gisstack web` ბეჭდავს. სერვერზე პორტი გაატარე ტუნელით (`ssh -L 8765:127.0.0.1:8765 user@server`) და ბმული შენს კომპიუტერზე გახსენი. token-ის ფაილია `/var/lib/gisstack-installer/web.token`. დაფის გვერდს სჭირდება `GISSTACK_FEATURES=dashboard`.

## Deploy preflight-ზე ჩერდება

წაიკითხე შეტყობინება: ის უთითებს, რა აკლია (დისკი, მეხსიერება, დაკავებული პორტი, არასწორი საათი). `gisstack scan` აჩვენებს, რომელი პროგრამა იკავებს, მაგალითად, 80 ან 443 პორტს. თითოეულზე გადაწყვიტე `--existing postgis=adopt,caddy=reuse,nginx=disable`-ით, ან გაათავისუფლე პორტი. შემოწმების გამოტოვება შეიძლება (`--skip-preflight`), მაგრამ შედეგზე შენ აგებ პასუხს.

## SSH-ის პრობლემები

* `Permission denied`: gis-stack პაროლს არასოდეს ითხოვს. გამოიყენე გასაღები (`--key`) ან agent.
* არა-root მომხმარებელს სჭირდება `sudo` პაროლის გარეშე (`sudo -n true` უნდა მუშაობდეს).
* `Host key verification failed` შენახული სერვერის პროფილით: სერვერის გასაღები აღარ ემთხვევა დაფიქსირებულს. ან სერვერი თავიდან აიგო, ან ვიღაც კავშირში ერევა. შეადარე ანაბეჭდი სერვერის კონსოლზე და თავიდან დააფიქსირე („სერვერები“ გვერდი, ან `replace=true` API-ში).
* კავშირი ჩერდება: gis-stack პასუხის გარეშე დაახლოებით ერთ წუთში ნებდება; შეამოწმე firewall და პორტი.

## პროგრამა არ მუშაობს

`gisstack status` აჩვენებს მდგომარეობას და პორტს. შემდეგ `gisstack logs -c stack.json <program> -f`. ხშირი მიზეზები: პორტი სხვა პროგრამას უკავია, GeoServer/Tomcat-ის heap-ისთვის მეხსიერება არ ჰყოფნის (შეამცირე კონფიგურაციაში), ან ხელით შეცვლილი კონფიგურაციის ფაილი უარყოფილია (MapProxy-ის გვერდი თავად MapProxy-ით ამოწმებს და ასლებს ინახავს). გადატვირთვა: `gisstack restart -c stack.json <program>`.

## RPM სისტემები (Rocky / Alma / Fedora)

ჩართე EPEL და CRB (ინსტალერი ამას აკეთებს) და გაითვალისწინე, რომ `pg_isready` PATH-ში არ არის: ბაზის შესამოწმებლად გამოიყენე `runuser -u postgres -- psql -c 'select 1'`. SELinux enforcing რჩება; სერვისის გასაშვებად ნუ გამორთავ, წაიკითხე `ausearch -m avc -ts recent`.

## განახლება ვერ ხერხდება

* „SHA-256 არ ემთხვევა“: ჩამოტვირთვა დაზიანდა ან შეცვალეს; ფაილი იშლება. სცადე ხელახლა; განმეორებისას შეგვატყობინე.
* „ხელმოწერა არასწორია“: გამოშვების `SHA256SUMS` ამ რეპოზიტორიის release workflow-მ არ მოაწერა ხელი. ნუ დააყენებ; შეგვატყობინე.
* „ხელმოწერა არ არის“ ან „cosign არ არის დაყენებული“ გაფრთხილებაა, თუ `GISSTACK_REQUIRE_SIGNATURE=1` არ არის დაყენებული.

## სად არის მტკიცებულებები

| რა | სად |
| --- | --- |
| ოპერაციები (deploy, restart, ცვლილებები) | `~/.gisstack/journal.jsonl` |
| ვებ/API-ით ვინ რა შეცვალა | `~/.gisstack/audit.log` |
| gis-stack-ის საკუთარი ლოგი | `~/.gisstack/gisstack.log` (`--log-level debug`) |
| გენერირებული პაროლები სერვერზე | `/etc/gisstack/credentials.txt` (root) |
| ბექაფები სერვერზე | `/var/backups/gisstack/stack/` |

პრობლემის შეტყობინებისას დაურთე `gisstack --version`, ბრძანება და შესაბამისი ჟურნალის სტრიქონები. `credentials.txt` და token-ები არასოდეს ჩასვა.
